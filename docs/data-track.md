## Context.dev — The Web Is Your Real-Time Database

### Summary
Build a product that reacts to the live web.

### Description

**Introduction**

Most software runs on stale data and can't see the internet as it is right now. Context.dev turns any website, company, person or news story into clean, structured data with one API call. You can combine train delays, live sneaker prices, GTA VI leaks and anything your heart imagines to combine them in novel ways.

**The challenge**

Every industry runs on information that sits on the open web, but it's spread across millions of pages in different formats, and it goes out of date overnight. Analysts still copy-paste prices, check supplier websites by hand and read the news to catch risks. Fact-checkers can't keep up with what gets shared online. Software still greets every new customer with the same generic screen.

Build a product that turns live web data into decisions, actions or experiences that weren't possible before.

Some examples for inspiration:

- GPU Rental Prices: compare GPU rental prices across cloud providers.
- Yapper Leaderboard: rank founders and startups by their activity on X. See how Stan built a similar leaderboard using Context.dev.
- cve.now: monitor newly disclosed security vulnerabilities.
- Ferndesk: personalize onboarding with company data and brand assets.

## MariaDB — Wikipedia Through Time.

### Summary
Build the tools Wikipedia is missing, powered by MariaDB's vector search (RAG) and system-versioned tables.

### Description

**INTRODUCTION**

Every time you open a Wikipedia article, MariaDB is working behind the scenes: it is the open-source database that stores and serves the world's largest encyclopedia. Yet much of Wikipedia's potential remains untapped. Search is still largely keyword-based, and the full edit history behind every article, a record of how human knowledge evolves, is rarely explored. AI and modern database features now make it possible to ask Wikipedia questions in plain language and to travel back in time through its content. MariaDB is bringing this challenge to Junction to see what the next generation of builders can create when these capabilities meet real Wikipedia data.

**CHALLENGE DESCRIPTION**

Your mission: build a tool for Wikipedia that doesn't exist yet, or that exists but is badly underused, with MariaDB at the core of your stack. The challenge has two tracks, and you pick the one that matches your ambition.

- **RAG TRACK** (recommended for most teams): use MariaDB's native vector search to build retrieval-augmented generation (RAG) functionality that let people ask questions of Wikipedia and get grounded, source-cited answers, for example a research assistant for the history of Finland.
- **SVT TRACK** (for advanced teams): use MariaDB system-versioned tables (SVT) to build tools that query how knowledge changes over time, for example showing what an article said on any given date, surfacing edit wars, or tracing how the story of a historical event has been rewritten.
- **BOTH** (for very advanced teams): combine the two, for example a RAG assistant that can answer "what did Wikipedia say about this in 2015, and what has changed since?"

### Judging

**JUDGING CRITERIA**

We're looking for the most useful and original tool for Wikipedia built on MariaDB. Judges will focus on effective and creative use of MariaDB RAG and/or system-versioned tables, technical execution and scalability across the provided datasets, real-world usefulness for Wikipedia readers or editors, and design and demo quality. Teams taking on the SVT track, or combining both tracks, will be recognised for the added technical ambition.
